### #3 의 귀속 — 우리 탓이 아니다 (대조 2종)
- 같은 케이블 TCP ping RTT **min 168 µs / avg 327 µs** → 단방향 84 µs. [측정]
- 우리 단방향 111.7 µs (4KiB `수신대기`). → TCP 대비 **1.5×**, 이상적 IB NIC 대비 56×. [도출]
- 호스트 pinned 로 바꿔도 **더 느리다**(574 µs) → dmabuf/RAW_STREAM 페널티가 아니다. [측정]
- **결론: 115 µs 하한은 NHI/Thunderbolt 경로의 고유 지연.** 소프트웨어로 줄일 대상이 아니라
  **횟수를 줄여 우회할 대상**이다.

## 2. 커스텀 집합통신 계층 (초석) — `step4/allreduce_mr.cpp`

2랭크 전용. ring/tree 불필요: 전량 교환 후 로컬 가산 = 바이트는 ring 과 동일, **홉은 1회로 최소**.
레일 수만큼 버퍼를 등분하고 레일별 QP 로 병렬 전송, `WRITE_WITH_IMM` 의 recv 완료가 도착 신호.

### 설계 결정 3개 (모두 실측으로 확정)
1. **dmabuf MR 은 HSA export 의 offset 으로 등록해야 한다.** `hipMemGetHandleForAddressRange` 로
   버퍼마다 export 하면 같은 슬랩의 fd 가 나와 offset 0 두 MR 이 같은 메모리를 가리킨다.
   증거: 피어가 `stage` 에 쓴 2.0 이 `mine` 을 덮어 `mine[0]=2.0`(기대 1.0) 이 됐다.
   수정 후 `mine off=0 / stage off=57344` → `verify=OK`.
2. **호스트 flag 별도 WR 은 쓸 수 없다.** dmabuf 는 RAW_STREAM 경로, 호스트 flag 는 일반 경로라
   같은 QP·RC 라도 순서가 보장되지 않는다. → `WRITE_WITH_IMM` recv 완료를 완료신호로 쓴다.
3. **선택적 시그널링이 가장 큰 단일 승리.** 매 WR `SIGNALED` → 32회당 1회로 바꿔
   229KiB 가 **395.8 → 266.4 µs**. 임계경로의 송신CQ 171.7 → 3.7 µs.

## 3. 가장 중요한 결론: 이 링크에서는 TP 보다 PP 다

고정비 115 µs 가 하드웨어 고유값이므로(§1 #3), 최적화 대상은 **집합통신의 크기가 아니라 횟수**다.

| 병렬화 | 스텝당 통신 횟수 | 스텝당 고정비 | 근거 |
|---|---:|---:|---|
| TP=2 (현재) | **56회** | 56 × 115 µs = **6.4 ms** | [측정] 레이어당 2회 × 32레이어 |
| PP=2 | **1회** (경계에서 hidden state 1번) | 1 × 115 µs = **0.115 ms** | [도출] |

PP=2 도 TP=2 와 똑같이 노드당 가중치 읽기를 절반(32 ms)으로 줄인다. 차이는 통신이 **56배** 싸다는 것.
PP 의 대가는 버블이고, 그건 continuous batching 으로 마이크로배치를 2개 이상 흘려 채운다.

### 스텝시간 전망

| 구성 | 스텝 | tok/s | 구분 |
|---|---:|---:|---|
| 현재 (vLLM TP=2 + NCCL) | 58 ms | 138 | [측정] |
| TP=2 + 자체 집합통신 | 32 + 7.4 = **39.4 ms** | ~203 | [추정] 56회 × 133 µs |
| PP=2 + 자체 p2p + 마이크로배치 2 | **~32 ms** | ~250 | [추정] 버블이 완전히 메워질 때 |
| 통신 0 (하한) | 32 ms | 250 | [도출] 메모리 루프라인 |
